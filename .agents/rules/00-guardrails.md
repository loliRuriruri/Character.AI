# 절대 규칙 (VRM 모션 작업)

## 작업 방식
- 한 번에 한 Phase만 수행한다. Phase를 임의로 합치거나 앞서가지 않는다.
- 각 Phase 종료 시 반드시 멈추고 사용자 확인을 기다린다.
- 추측으로 코드를 작성하지 않는다. 근거가 없으면 "확인 필요"라고 보고하고 멈춘다.
- 파일을 수정하기 전에 반드시 먼저 읽는다.
- 대규모 일괄 수정 금지. 한 번에 1~3개 파일 단위로 변경하고 그때마다 빌드/실행을 확인한다.

## 정보 신뢰 우선순위 (충돌 시 위쪽이 이긴다)
1. 이 저장소에 실제 설치된 패키지의 소스/타입 정의 (node_modules)
2. `three-vrm-api-facts` 스킬에 기록된 검증 사실
3. VRM 공식 스펙 (github.com/vrm-c/vrm-specification)
4. @pixiv/three-vrm 공식 저장소의 examples
5. three.js 공식 문서
6. 그 외 블로그/커뮤니티 (참고만, 근거로 쓰지 말 것)

검색 결과 요약만 보고 판단하지 않는다. 반드시 실제 소스/문서를 연다.

## 절대 금지
- LLM(프롬프트)이 본 각도, Euler, quaternion, 월드 좌표를 생성하게 만들기
- `vrm.humanoid.getRawBoneNode(...)` 결과에 절차적 회전을 매 프레임 직접 대입
- `AnimationAction.stop()` 으로 제스처 종료 (반드시 fadeOut / crossFade 사용)
- `vrm.update()` 를 한 프레임에 두 번 이상 호출
- 원인 미확인 상태에서 IK, 새 라이브러리, 패키지 업그레이드 추가
- three 또는 @pixiv/three-vrm 버전을 사용자 승인 없이 변경
- 증상을 숨기기 위한 임시 각도 보정값(magic number) 삽입
- 기존 Chat / TTS / UI 코드 경로를 이번 작업 범위로 끌어들이기
- 15개 제스처를 한꺼번에 구현하기

## 코드 규칙
- 모든 아바타 transform 소유권은 단일 컨트롤러(MotionDirector)가 갖는다.
  React 컴포넌트, 이벤트 핸들러, 타이머가 본을 직접 만지면 안 된다.
- 신규 코드는 반드시 feature flag 뒤에 둔다. flag OFF면 기존 동작이 100% 그대로여야 한다.
- flag ON일 때 legacy 본 조작 코드는 완전히 실행되지 않아야 한다. 동시 실행은 최악이다.
- 매직넘버는 상수/설정 객체로 분리하고 주석에 근거를 남긴다.

## 보고 규칙
- 모든 산출 문서는 docs/vrm-motion/ 에 저장한다.
- 참조한 URL은 접속 날짜와 함께 기록한다.
- 실패하거나 확신이 없으면 그대로 보고한다. 성공한 척하지 않는다.
- 시각적 결과가 필요한 항목은 브라우저 서브에이전트로 스크린샷/녹화를 남긴다.
