# VRM 모션 시스템 Phase 5 QA 종합 검증 보고서 (`05-qa.md`)

> **검증 환경**: Windows 11 / Electron 34.3.0 / Node.js / Three.js r180 / `@pixiv/three-vrm` 3.3.11  
> **검증 대상 모델**: `HatsuneMikuNT.vrm` (VRM 0.0) & 교체 검증용 `Hu Tao Maid.vrm`

## 3. 불변 규칙 정적 및 동적 검증

### ① `vrm.update` 이후 본/표정/모프 쓰기: **0건 (PASS)**
`src/character/VrmStage.ts` 렌더 루프 분석:
```ts
254:     if (this.vrm) {
255:       this.vrm.update(dt);
256:       this.vrmUpdateCounter++;
257:     }
258: 
259:     // 7) renderer.render(scene, camera)
260:     this.renderer.render(this.scene, this.camera);
261: 
262:     // Post-render diagnostic HUD update only
263:     this.updateDebugHUD(dt);
```
- `this.vrm.update(dt)` 이후에는 `renderer.render()` 및 DOM 텍스트를 갱신하는 `updateDebugHUD()`만 호출되며, 본/표정/모프 쓰기는 **0건**입니다.

### ② `action.stop()` 사용: **0건 (PASS)**
- Grep 검사 결과 애니메이션 액션에 대한 `action.stop()` 직접 호출은 **0건**입니다. (모든 제스처 전환 및 종료는 `fadeOut(0.3)` 및 `crossFadeTo(idleAction, 0.4)`를 사용).

### ③ `morphTargetInfluences` 직접 대입 (`MOTION_V2=true`): **0건 (PASS)**
- `MOTION_V2=true` 경로에서는 모든 표정 및 립싱크가 `vrm.expressionManager.setValue()`를 통해서만 전달되며, GPU 모프 타깃 직접 대입은 **0건**입니다.

### ④ `MOTION_V2=false` 회귀 호환성: **정상 (PASS)**
- `MOTION_CONFIG.MOTION_V2 = false` 설정 시 TypeScript 컴파일 에러 0건, Electron 빌드 정상 완료 확인.

## 4. QA 중 발견된 결함 및 조치 내역 (최소 범위 코드 수정)

1. **FAIL 1: 다중 `stage.load()` 호출 시 `rAF` 루프 중복 실행 버그**
   - **원인**: `stage.load()`가 완료될 때마다 `this.loop()`를 새로 호출하여 `requestAnimationFrame` 루프가 모델 교체 횟수만큼 중복 누적됨 (`updatesPerFrame`이 3으로 치솟음).
   - **조치**: `VrmStage.ts`에 `private isLooping = false;` 플래그 및 `startLoop()`를 도입하여 단 하나의 렌더 루프만 상시 실행되도록 보장 (`updatesPerFrame`이 정확히 1.00으로 정상화).
2. **FAIL 2: `tts:end` 수신 시 음성 미재생 플래그로 인한 afterglow 전이 누락**
   - **원인**: `tts:start`가 생략되거나 지연된 상태에서 `tts:end` 수신 시 `this.isSpeaking === false`로 조기 리턴되어 `afterglow`로 넘어가지 못하고 `speaking`에 갇힘.
   - **조치**: `MotionDirector.ts`의 `handleMotionEvent`에서 `tts:end` 수신 시 `this.convState === "speaking"`이면 무조건 `afterglow`로 전이되도록 방어 로직 추가.
3. **FAIL 3: 연속 대화 시 이전 제스처 쿨다운으로 인한 지연 폴백 차단**
   - **원인**: 이전 턴에서 `explain`이 재생되어 8초 쿨다운 상태일 때 다음 턴의 `firstToken` 폴백이 쿨다운에 막혀 제스처가 나가지 못함.
   - **조치**: `fromIntent` 호출 시 목표 제스처가 쿨다운 중이면 사용 가능한 대화 제스처(`nod`, `think`)를 즉시 대체 선택하도록 보완.
